## 📖 项目概述

SERL (Sample-Efficient Robotic Reinforcement Learning) 是一个用于机器人操作任务的**样本高效强化学习**软件套件。该项目专注于在真实机器人和仿真环境中快速训练强化学习策略。

**核心特点：**
- ✅ 样本高效：能够用少量样本快速学习
- ✅ 异步架构：Actor-Learner 分离，支持并行训练
- ✅ 真实/仿真：同时支持 MuJoCo 仿真和真实 Franka/Aubo 机器人
- ✅ 视觉 + 状态：支持从状态或图像观测训练
- ✅ 人机协作：支持人类示教和在线干预 (HIL-SERL)

## 🔄 数据流和训练流程

### 异步训练架构

```
时间轴：
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Actor 节点 (与环境交互):
│
├─ 初始化: 创建环境、Agent
│
├─ 随机探索阶段 (前 random_steps 步):
│  └─ 采样随机动作 → 环境执行 → 收集经验 → 发送到 DataStore
│
├─ 策略训练阶段:
│  ├─ 从 Agent 采样动作 (带探索噪声)
│  ├─ 环境执行动作
│  ├─ 收集经验发送到 DataStore
│  └─ 接收 Learner 更新的参数
│
└─ 评估阶段:
   └─ 使用确定性策略评估性能

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Learner 节点 (训练策略):
│
├─ 初始化: 创建 Agent、Replay Buffer、TrainerServer
│
├─ 填充缓冲区阶段:
│  └─ 从 DataStore 接收数据 → 填充到 Replay Buffer
│     (等待至 training_starts 步)
│
├─ 训练循环:
│  ├─ 从 Replay Buffer 采样 batch
│  ├─ 计算损失并更新网络参数:
│  │  ├─ 更新 Critic 网络 (Q 函数)
│  │  ├─ 更新 Actor 网络 (策略)
│  │  └─ 更新 Target 网络
│  ├─ 定期发送参数到 Actor (每 steps_per_update 步)
│  └─ 记录训练指标 (W&B)
│
└─ 保存模型:
   └─ 定期保存检查点
```

### 关键组件交互

```python
# 1. Actor 端 - 数据收集
obs, _ = env.reset()
for step in range(max_steps):
    # 采样动作
    if step < random_steps:
        action = env.action_space.sample()  # 随机探索
    else:
        action = agent.sample_actions(obs)  # 使用策略
    
    # 执行动作
    next_obs, reward, done, truncated, info = env.step(action)
    
    # 存储经验
    data_store.insert({
        'observations': obs,
        'actions': action,
        'next_observations': next_obs,
        'rewards': reward,
        'masks': 1.0 - done,
        'dones': done or truncated,
    })
    
    # 接收新参数 (异步，自动更新)
    # client.recv_network_callback(update_params)

# 2. Learner 端 - 策略训练
while replay_buffer.size < training_starts:
    batch = data_store.recv()  # 接收 Actor 数据
    replay_buffer.insert(batch)

for step in range(max_steps):
    # 从 Buffer 采样
    batch = replay_buffer.sample(batch_size * utd_ratio)
    
    # 更新算法
    agent, update_info = agent.update(batch, utd_ratio)
    
    # 发送新参数到 Actor
    if step % steps_per_update == 0:
        server.publish_network(agent.state.params)
```

## 🧠 核心算法详解

### 1. SAC (Soft Actor-Critic)

**适用场景：** 状态观测的连续控制任务

**网络结构：**

```
Actor (策略网络):
  输入: 状态 s
  隐藏层: MLP [256, 256]
  输出: 动作分布 π(a|s) ~ N(μ, σ)

Critic (Q 网络, 双网络):
  输入: [状态 s, 动作 a]
  隐藏层: MLP [256, 256]
  输出: Q 值估计 Q(s, a)
```

**损失函数：**
```python
# 1. Critic 损失 (TD Error)
target_q = reward + γ * min(Q'₁(s', a'), Q'₂(s', a')) - α*log π(a'|s')
critic_loss = MSE(Q(s,a), target_q)

# 2. Actor 损失 (最大化 Q 值 - 最大化熵)
actor_loss = E[α*log π(a|s) - Q(s, a)]

# 3. 温度参数损失 (自动调整探索)
alpha_loss = -α * (log π(a|s) + target_entropy)
```

### 2. DrQ (Data Regularized Q)

**适用场景：** 图像观测的视觉操作任务

**特点：**
- 使用卷积编码器处理图像
- 数据增强：随机裁剪 (Random Crop)
- 提高样本效率

**网络结构：**
```
Vision Encoder:
  输入: RGB 图像 (H, W, 3)
  编码器: ResNet-10 / MobileNet
  输出: 特征向量 (512-d)
         ↓
Actor/Critic (与 SAC 相同)
```

**数据增强技巧：**
```python
# 对同一图像应用不同的随机裁剪
image_augmented_1 = random_crop(image, crop_size=84)
image_augmented_2 = random_crop(image, crop_size=84)

# 用于 Q 函数的正则化
Q_loss = MSE(Q(aug1), target) + MSE(Q(aug2), target)
```

## 🔧 关键超参数

| 参数 | 默认值 | 说明 | 调优建议 |
|------|--------|------|---------|
| `batch_size` | 256 | 训练批次大小 | 增大可提高稳定性，但需要更多内存 |
| `utd_ratio` | 1.0 | Update-to-Data 比率 | 增大可加快学习，但可能过拟合 |
| `critic_actor_ratio` | 8 | Critic/Actor 更新比 | Critic 更新更频繁，提高价值估计准确性 |
| `random_steps` | 300-1000 | 随机探索步数 | 复杂任务需要更多 |
| `training_starts` | 300-1000 | 开始训练的步数 | 确保缓冲区有足够多样的数据 |
| `replay_buffer_capacity` | 1M | 缓冲区容量 | 根据内存调整 |
| `learning_rate` | 3e-4 | 学习率 | 不稳定时减小 |

## 📊 性能优化技巧

### 1. 提高样本效率
- ✅ 加载人类示教数据 (BC pretraining)
- ✅ 在线人类干预 (SpaceMouse)
- ✅ 奖励塑形 (Reward Shaping)

### 2. 加速训练
- ✅ 增大 `utd_ratio` (更频繁的梯度更新)
- ✅ 使用 GPU 加速 (JAX 自动支持)
- ✅ 减小评估频率 (`eval_period`)

### 3. 提高稳定性
- ✅ 增大 `batch_size`
- ✅ 降低学习率
- ✅ 使用 target network (自动启用)

## 🐛 常见问题

**Q1: Actor 一直等待 Learner？**
```
A: 确保先启动 Learner，再启动 Actor
   检查 IP 地址配置是否正确 (--ip 参数)
```

**Q2: 训练不收敛？**
```
A: 1. 检查奖励函数设计是否合理
   2. 增加随机探索步数 (random_steps)
   3. 减小学习率
   4. 增加人类示教数据
```

**Q3: GPU 内存不足？**
```
A: 1. 减小 batch_size
   2. 减小 replay_buffer_capacity
   3. 使用更小的视觉编码器 (small_encoder)
```

**Q4: 真实机器人安全问题？**
```
A: 1. 设置合理的动作限幅
   2. 使用阻抗控制器
   3. 部署急停按钮
   4. 在仿真中充分测试
```
