# 场景与机器人组织方案分析

## 📋 当前状态

### 现有实现
1. **场景XML文件**：
   - `default.xml`: 包含硬编码的Aubo_i5机器人
   - `grasping.xml`: 只包含环境（地面、桌子、光照、相机），无机器人
   - 其他场景：部分包含机器人，部分不包含

2. **代码结构**：
   - `env_factory.py`: 直接使用场景XML路径，无动态组合
   - `XMLSplicer`: 提供动态组合功能（scene → mount → manipulator → gripper），但未被使用
   - `SimulationRobotEnv`: 直接加载XML文件，无组合逻辑

3. **RobotConfig**：
   - 当前只包含逻辑配置（dof、controller_type等）
   - 不包含物理配置（机器人模型、夹爪、相机等）

---

## 🎯 方案对比

### 方案1：场景中不包含机器人（推荐 ⭐）

**核心思想**：
- 场景 = 环境（地面、光照、物体、相机位置等）
- 机器人配置 = 机器人模型 + 夹爪 + 传感器
- 运行时动态组合

**架构**：
```
场景 (Scene)
  ├── 环境元素（地面、光照、物体）
  └── 相机位置定义

机器人配置 (RobotConfig)
  ├── 机器人模型 (manipulator)
  ├── 夹爪 (gripper)
  ├── 安装座 (mount)
  └── 传感器配置 (cameras, etc.)

运行时组合
  Scene + RobotConfig → XMLSplicer → 完整XML
```

**代码组织**：
```python
# 扩展 RobotConfig
class RobotConfig:
    def __init__(
        self,
        name: str,
        robot_type: str,
        dof: int,
        # 新增物理配置
        manipulator_name: str,      # "franka_panda", "aubo_i5"
        gripper_name: Optional[str] = None,  # "panda_hand", "robotiq_2f85"
        mount_name: Optional[str] = None,    # "floor_left", "cylinder"
        camera_config: Optional[Dict] = None,  # 相机配置
        ...
    ):
        # 逻辑配置
        self.name = name
        self.dof = dof
        self.controller_type = controller_type
        # 物理配置
        self.manipulator_name = manipulator_name
        self.gripper_name = gripper_name
        self.mount_name = mount_name
        self.camera_config = camera_config
```

**使用示例**：
```python
# 创建环境
env = make_sim_env(
    robot_name="franka_panda",      # 选择机器人
    task_name="pick_cube",
    scene="grasping",                # 选择场景（不包含机器人）
    gripper="panda_hand",            # 可选：指定夹爪
    mount="floor_left",              # 可选：指定安装座
    camera_config={                  # 可选：相机配置
        "wrist_camera": "realsense_d435",
        "fixed_camera": "frontview"
    }
)
```

**优势** ✅：
1. **高度灵活**：同一场景可搭配不同机器人
   ```python
   # 同一场景，不同机器人
   env1 = make_sim_env("franka_panda", "pick_cube", scene="grasping")
   env2 = make_sim_env("aubo_i5", "pick_cube", scene="grasping")
   env3 = make_sim_env("ur5e", "pick_cube", scene="grasping")
   ```

2. **易于扩展**：新增机器人/夹爪/相机无需修改场景
   - 新增机器人：只需添加机器人模型文件
   - 新增夹爪：只需添加夹爪模型文件
   - 场景保持不变

3. **组合丰富**：支持多种组合方式
   ```python
   # 同一任务，不同配置
   env1 = make_sim_env("franka_panda", "pick_cube", gripper="panda_hand")
   env2 = make_sim_env("franka_panda", "pick_cube", gripper="robotiq_2f85")
   ```

4. **代码复用**：场景和机器人配置解耦
   - 场景可被多个任务复用
   - 机器人配置可被多个场景复用

5. **符合现有架构**：已有`XMLSplicer`工具，可直接使用

**劣势** ❌：
1. **运行时组合**：需要XML拼接，略微增加初始化时间
2. **配置复杂**：需要管理更多配置项
3. **兼容性检查**：需要验证机器人-夹爪-场景的兼容性

**实施建议**：
1. 扩展`RobotConfig`，添加物理配置字段
2. 修改`env_factory.py`，使用`XMLSplicer`动态组合
3. 清理现有场景XML，移除硬编码的机器人
4. 添加兼容性检查机制

### 方案2：场景中包含机器人

**核心思想**：
- 场景 = 完整环境（环境 + 机器人 + 夹爪 + 传感器）
- 任务和场景一一对应
- 静态绑定

**架构**：
```
场景 (Scene)
  ├── 环境元素
  ├── 机器人模型（硬编码）
  ├── 夹爪（硬编码）
  └── 传感器（硬编码）

任务 (Task)
  └── 指定场景名称

运行时
  Task → Scene → 直接加载XML
```

**代码组织**：
```python
# Task 中指定场景
class PickCubeTask(BaseTask):
    def __init__(self, ...):
        self.scene_name = "pick_cube_franka"  # 硬编码场景
        # 或从配置读取
        self.scene_name = self._get_scene_for_robot(robot_config.name)

# env_factory 中
def make_sim_env(robot_name, task_name, ...):
    task = _get_task_instance(...)
    scene_name = task.get_scene_name()  # 从任务获取场景
    xml_path = _get_scene_xml_path(scene_name)
    ...
```

**使用示例**：
```python
# 创建环境（场景由任务决定）
env = make_sim_env(
    robot_name="franka_panda",  # 用于选择对应的场景
    task_name="pick_cube"
    # scene 参数不再需要，由任务决定
)
```

**优势** ✅：
1. **简单直接**：场景即用，无需组合
2. **性能好**：无需运行时XML拼接
3. **配置简单**：用户只需选择任务和机器人
4. **易于调试**：场景XML完整，可直接查看

**劣势** ❌：
1. **灵活性差**：同一任务+不同机器人需要不同场景
   ```python
   # 需要创建多个场景文件
   pick_cube_franka.xml
   pick_cube_aubo.xml
   pick_cube_ur5e.xml
   ```

2. **代码冗余**：场景间大量重复代码
   - 环境部分（地面、光照、物体）重复
   - 只有机器人部分不同

3. **扩展困难**：
   - 新增机器人：需要为每个任务创建新场景
   - 新增夹爪：需要修改所有相关场景
   - 场景数量爆炸：N个任务 × M个机器人 = N×M个场景

4. **维护成本高**：
   - 修改环境元素需要更新所有场景
   - 难以保证场景间一致性

5. **不符合现有工具**：已有`XMLSplicer`但无法充分利用

---

## 💡 推荐方案：方案1（场景中不包含机器人）

### 理由
1. **符合项目架构**：已有`XMLSplicer`工具，可直接使用
2. **长期可维护性**：场景和机器人解耦，易于扩展
3. **灵活性**：支持丰富的组合方式
4. **代码复用**：最大化代码复用率

### 实施步骤

#### 步骤1：扩展 RobotConfig
```python
# mujoco_env/tasks/base_task.py
class RobotConfig:
    def __init__(
        self,
        name: str,
        robot_type: str,
        dof: int,
        controller_type: str = "joint_position",
        control_freq: int = 20,
        has_gripper: bool = True,
        # 新增：物理配置
        manipulator_name: Optional[str] = None,
        gripper_name: Optional[str] = None,
        mount_name: Optional[str] = None,
        camera_config: Optional[Dict[str, Any]] = None,
    ):
        # 逻辑配置
        self.name = name
        self.robot_type = robot_type
        self.dof = dof
        self.controller_type = controller_type
        self.control_freq = control_freq
        self.has_gripper = has_gripper
        
        # 物理配置（从robot_class获取默认值）
        self.manipulator_name = manipulator_name or name
        self.gripper_name = gripper_name
        self.mount_name = mount_name
        self.camera_config = camera_config or {}
```

#### 步骤2：修改 robot_config 类
```python
# mujoco_env/robot_config/franka_panda.py
class FrankaPandaRobot:
    @staticmethod
    def get_config(
        controller_type: str = "joint_position",
        control_freq: int = 20,
        has_gripper: bool = True,
        gripper_name: Optional[str] = None,
        mount_name: Optional[str] = None,
        **kwargs
    ) -> RobotConfig:
        # 默认夹爪
        if has_gripper and gripper_name is None:
            gripper_name = "panda_hand"
        
        return RobotConfig(
            name=FrankaPandaRobot.NAME,
            robot_type="franka",
            dof=FrankaPandaRobot.DOF,
            controller_type=controller_type,
            control_freq=control_freq,
            has_gripper=has_gripper,
            manipulator_name="franka_panda",  # 或 "Panda"
            gripper_name=gripper_name,
            mount_name=mount_name,
        )
```

#### 步骤3：修改 env_factory
```python
# mujoco_env/envs/env_factory.py
def make_sim_env(
    robot_name: str,
    task_name: str,
    scene: Optional[str] = None,
    gripper: Optional[str] = None,
    mount: Optional[str] = None,
    camera_config: Optional[Dict] = None,
    ...
):
    # 1. 获取机器人配置
    robot_class = get_robot(robot_name)
    robot_config = robot_class.get_config(
        controller_type=controller_type,
        control_freq=int(control_freq),
        gripper_name=gripper,  # 传递夹爪配置
        mount_name=mount,      # 传递安装座配置
    )
    
    # 2. 创建任务
    task = _get_task_instance(...)
    
    # 3. 动态组合XML
    from mujoco_env.mujoco_env.utils.xml_splice import XMLSplicer
    
    splicer = XMLSplicer(
        name=f"{robot_name}_{task_name}",
        scene=scene or "default",
        mount=robot_config.mount_name,
        manipulator=robot_config.manipulator_name,
        gripper=robot_config.gripper_name,
        attached_body=robot_config.gripper_attach_point,  # 需要定义
    )
    
    xml_path = splicer.get_xml_path()
    
    # 4. 创建环境
    env = SimulationRobotEnv(
        xml_path=xml_path,
        task=task,
        ...
    )
    
    return env
```

#### 步骤4：清理场景XML
- 移除场景XML中的硬编码机器人
- 保留环境元素（地面、光照、物体、相机位置）
- 确保场景可被任意机器人使用

#### 步骤5：添加兼容性检查
```python
# mujoco_env/utils/compatibility.py
def check_robot_gripper_compatibility(
    robot_name: str,
    gripper_name: str
) -> bool:
    """检查机器人和夹爪是否兼容"""
    compatibility_map = {
        "franka_panda": ["panda_hand", "robotiq_2f85"],
        "aubo_i5": ["robotiq_2f85", "schunk_wsg50"],
        ...
    }
    return gripper_name in compatibility_map.get(robot_name, [])
```

## 🎯 最终建议

**采用方案1（场景中不包含机器人）**，原因：

1. **长期收益**：虽然初期实施稍复杂，但长期维护成本低
2. **架构一致**：充分利用现有`XMLSplicer`工具
3. **灵活性**：支持丰富的组合方式，满足未来需求
4. **可扩展性**：新增机器人/夹爪/相机无需修改场景

**实施优先级**：
1. **高优先级**：扩展`RobotConfig`，修改`env_factory`使用`XMLSplicer`
2. **中优先级**：清理场景XML，移除硬编码机器人
3. **低优先级**：添加兼容性检查和错误处理

## 📝 代码组织建议

### 目录结构
```
mujoco_env/
├── assets/
│   ├── scenes/              # 场景（不含机器人）
│   │   ├── default.xml
│   │   ├── grasping.xml
│   │   └── assemble.xml
│   ├── models/
│   │   ├── manipulators/    # 机器人模型
│   │   ├── grippers/         # 夹爪模型
│   │   └── mounts/           # 安装座模型
│   └── objects/              # 物体模型
├── robot_config/             # 机器人配置（逻辑+物理）
│   ├── franka_panda.py
│   └── aubo_i5.py
└── tasks/                    # 任务定义
    └── pick_cube.py
```

### 配置层次
```
用户调用
  ↓
env_factory.make_sim_env()
  ├── robot_name → robot_config (逻辑+物理配置)
  ├── scene → 场景XML
  ├── gripper → 夹爪选择
  └── task → 任务定义
  ↓
XMLSplicer (动态组合)
  ↓
SimulationRobotEnv (加载完整XML)
```

## ✅ 总结

**推荐方案1**，通过扩展`RobotConfig`和利用`XMLSplicer`实现场景与机器人的解耦，提供最大的灵活性和可扩展性，符合项目现有架构，长期维护成本低。
